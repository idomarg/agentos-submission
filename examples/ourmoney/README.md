# Example — OurMoney

> **Case study #1 של AgentOS.** קבצי ה-memory כאן הם דוגמה מייצגת לאיך AgentOS עובד בפרויקט מוצר מורכב ומתגלגל. (ערכים מייצגים, לא snapshot חי.)

---

## מה זה OurMoney

מוצר **אישי** לניהול תקציב והון אישי — אפליקציית web (Next.js + Supabase) שמחליפה את Riseup לניהול תזרים חודשי, ומוסיפה מעליו שכבת ניהול הון (נדל"ן, קרקעות, מניות פרטיות, הלוואות, משכנתא, מעשר). משתמשים: בני זוג עם חשבון משותף.

זהו פרויקט מוצר **מורכב** — הרבה issues, הרבה סשנים, החלטות ארכיטקטוניות אמיתיות. בדיוק סוג הפרויקט שבו "שכחת הקשר" בין סשנים הכי כואבת, ושבו AgentOS מוכיח את עצמו.

---

## למה זה דוגמה טובה ל-AgentOS

- **רבגוני** — ייבוא נתונים, CRUD, דשבורד, מנוע חוקים, מנוע קטגוריזציה AI, שכבת הון.
- **מתגלגל** — נבנה על פני סשנים רבים; בלי `STANDUP.md` כל סשן היה מתחיל מאפס.
- **החלטות נעולות אמיתיות** — למשל "אין LLM בתוך האפליקציה" (ראה `DECISIONS.md`).
- **מנוע AI offline** — Claude מכין הצעות סיווג דרך Supabase MCP; המשתמש מאשר. דוגמה מצוינת ל"human in the loop".

---

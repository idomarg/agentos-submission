# Project Routing — מתי Linear, מתי ישירות

פרוטוקול ההחלטה: לפני שנוגעים בקובץ, לאן מנתבים את העבודה.

---

## שאלה 1 — האם קיים פרויקט Linear ל-repo הזה?

בדוק אם `CLAUDE.md` מכיל סקשן `## Linear project`.

### אם **אין** פרויקט Linear:
- **Level 0** (typo, שורה אחת): בצע ישירות.
- **כל עבודה משמעותית**: עצור. אמור — "אין עדיין פרויקט Linear ל-repo הזה. לכל עבודה אמיתית כדאי להקים אחד. שאכלול את זה כצעד 1 בתוכנית?"
- **אל** תקים פרויקט Linear באופן ספונטני — זה דורש תוכנית מאושרת.

### אם **קיים** פרויקט Linear:
- המשך לשאלה 2.

---

## שאלה 2 — איזו רמת עבודה?

| מצב | ניתוב |
|---|---|
| "מה הבא" / "תמשיך" | קח את ה-issue הבא שאפשר לתבוע (`/start-issue`). |
| feature חדש שהגיע בתוכנית מאושרת | הוסף issues לפרויקט הקיים (Increment). |
| עבודה קטנה ישירה בלי תוכנית | סווג Level 0/1/2/3 לפני שנוגעים בקובץ. |
| feature/מערכת (Level 3) בלי תוכנית | **עצור.** כתוב תוכנית, חכה לאישור, ואז issues. |

---

## כלל הזהב

> **אפליקציה אחת = פרויקט Linear אחד.** לעולם לא פרויקט חדש לכל feature.

feature חדש מתווסף **כ-issues** לפרויקט הקיים, לא כפרויקט נפרד.

---

## עבודה מקבילה

אם `STANDUP.md` מראה issue ו-branch פעילים שאינם ה-branch שלך — המשימה תפוסה על ידי סשן אחר. אל תתבע אותה. קח את הבא בתור. **Linear הוא הבורר.**

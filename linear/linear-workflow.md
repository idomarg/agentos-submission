# Linear Workflow — Linear כמקור האמת

הקונבנציה שלפיה AgentOS מנהל משימות מול Linear. המטרה: מקור אמת אחד למה נעשה, מה בעבודה, ומה הבא בתור — ושני סוכנים לא דורכים זה על זה.

---

## עקרונות יסוד

1. **אפליקציה אחת = פרויקט Linear אחד.** לעולם לא פרויקט חדש לכל feature. feature חדש = issues חדשים באותו פרויקט.
2. **כל משימה משמעותית = issue לפני שמתחילים.** עם Acceptance Criteria.
3. **חריג Level 0**: typo, פורמט, שורה אחת, פחות מ-5 דקות — ישירות, בלי issue.

---

## סיווג עבודה (Levels)

| Level | דוגמאות | פעולה |
|---|---|---|
| 0 — טריוויאלי | typo, הערה, שורה אחת | ישירות. בלי Linear. |
| 1 — תיקון קטן | bug fix, UI tweak, <50 שורות | issue קליל, ואז ביצוע. |
| 2 — רב־קובצי | שינוי התנהגות, refactor, שינוי נתונים | זרימת Linear מלאה. |
| 3 — feature/מערכת | מודול חדש, אינטגרציה, רב־issue | עצור. תוכנית. אישור. ואז issues. |

בספק — בחר את הרמה הגבוהה יותר.

---

## נעילה תלת־שכבתית (Three-tier mutex)

כדי ששני סוכנים לא יתפסו אותה משימה, כל issue פעיל ננעל בשלושה:

- **Assignee** — מוקצה לסוכן/סשן שתפס.
- **Status** — In Progress.
- **Branch** — branch פתוח בשם התואם.

שלושתם יחד = הוכחת בעלות. אם issue מסומן כך — סוכן אחר בוחר את הבא בתור.

---

## שמות branch

`<user>/<issue-id>-<slug>` — בדיוק ה-`gitBranchName` ש-Linear מייצר ל-issue. מילה במילה, בלי המצאות.

דוגמה: `idomarg/app-42-import-csv`.

---

## מחזור חיים של issue

```
Backlog → (claim) → In Progress → (PR) → In Review → (merge) → Done
```

1. **Claim** — `/start-issue` נועל ופותח branch.
2. **Work** — מימוש מול ה-Acceptance Criteria בלבד.
3. **PR** — פתיחת PR; `/review-pr` בודק מול criteria + decisions + סטנדרטים.
4. **Merge** — מיזוג (למשל squash + מחיקת branch).
5. **Close** — עדכון ה-issue בתגובה קצרה בעברית: מה נעשה.

---

## מיזוג ובדיקות

- האות האמיתי לאיכות הוא build/typecheck מקומי ירוק — אותו דבר שה-CI מריץ.
- בדיקת CI שעדיין רצה (PENDING) אינה בהכרח חוסם, אם ה-build המקומי עבר ואין branch protection. בדיקת CI שנכשלה (ERROR) — חוסם אמיתי, לבדוק לפני מיזוג.

> **סטטוס יישום:** הקונבנציה הזו **בשימוש אמיתי** בפרויקטים (ראה `examples/`), מופעלת ידנית/חצי־אוטומטית. סנכרון Linear API דו־כיווני מלא הוא **Future**.

# תבנית Issue — AgentOS

מבנה אחיד ל-issue ב-Linear. issue טוב מאפשר לסוכן לעבוד בלי לשאול שאלות באמצע.

---

## תבנית

```markdown
## כותרת
<פועל + מושא קצר. דוגמה: "ייבוא תנועות מקובץ CSV">

## הקשר / למה
<משפט–שניים: למה המשימה הזו קיימת, איזה כאב היא פותרת.>

## Acceptance Criteria
- [ ] <תנאי קבלה מדיד 1>
- [ ] <תנאי קבלה מדיד 2>
- [ ] <תנאי קבלה מדיד 3>

## Scope / גבולות
- בתוך ה-scope: <מה כן>
- מחוץ ל-scope: <מה לא — כדי למנוע זחילת scope>

## Level
<0 / 1 / 2 / 3>

## תלויות
<issues שצריכים להסתיים קודם, או "אין">

## הערות טכניות
<קבצים רלוונטיים, גישה מומלצת, gotchas ידועים>
```

---

## כללים ל-Acceptance Criteria טובים

- **מדידים** — אפשר לסמן ✓/✗ בלי פרשנות.
- **ממוקדי תוצאה** — מה המשתמש יוכל לעשות, לא איך מימשת.
- **3–6 פריטים** — פחות מדי = לא ברור; יותר מדי = ה-issue גדול מדי, פצל.

---

## דוגמה ממולאת

```markdown
## כותרת
מסך אישור הצעות סיווג (/categorize)

## הקשר / למה
ה-AI מכין הצעות סיווג; המשתמש צריך מסך לאשר/לדחות אותן בכמות.

## Acceptance Criteria
- [ ] כל הצעה pending מוצגת עם בית עסק, קטגוריה מוצעת, ורמת ביטחון.
- [ ] אישור מחיל את הקטגוריה על כל התנועות של אותו בית עסק.
- [ ] דחייה משנה את הסטטוס ל-rejected.
- [ ] כותרת מציגה מונה של הצעות pending.

## Scope / גבולות
- בתוך: מסך האישור והפעולות.
- מחוץ: חישוב ההצעות עצמן (issue נפרד).

## Level
2
```

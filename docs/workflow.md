# Workflow — זרימת העבודה המלאה

המדריך המעשי: איך נראה יום עבודה עם AgentOS, מקצה לקצה.

---

## הכלל המרכזי

> **קוראים בהתחלה (`/prime`), כותבים בסוף (`/wrap-up`).**

כל מה שביניהם הוא ביצוע. כל מה שמחוץ לזה — נשכח.

---

## שלב 1 — Prime (תחילת סשן)

```
/prime
```

הסוכן קורא `CLAUDE.md` + `STANDUP.md` + `DECISIONS.md`, בודק branch ו-status, ומדווח בפסקה: פרויקט, משימה פעילה, branch, הצעד הבא. **קריאה בלבד — אין שינויים.**

אם `STANDUP.md` מראה issue/branch של סשן אחר — לא תובעים אותו.

---

## שלב 2 — Start issue (תפיסת משימה)

```
/start-issue
```

תופס את ה-issue הבא מ-Linear, נועל תלת־שכבתית (assignee + status + branch), פותח branch בשם התואם, וקורא את ה-Acceptance Criteria.

- Level 0 → דלג, בצע ישירות.
- Level 3 בלי תוכנית → עצור, כתוב תוכנית, חכה לאישור.

---

## שלב 3 — Work loop (ביצוע)

מימוש **מול ה-Acceptance Criteria בלבד**. עקרונות:

- לא לחרוג מגבולות ה-issue. scope חדש = issue חדש.
- שינויים קטנים ישירות; גדולים — פרק.
- כתוב קוד שנקרא כמו הקוד שסביבו.
- לא לשבור החלטה ב-`DECISIONS.md`.

---

## שלב 4 — Review PR (שער איכות)

```
/review-pr
```

בדיקה מול שלושה: Acceptance Criteria, `DECISIONS.md`, וסטנדרטי קוד. אימות מקומי (`typecheck`/`build`/`tests`) ירוק לפני מיזוג. correctness לפני סגנון.

---

## שלב 5 — Wrap-up (סוף סשן)

```
/wrap-up
```

**שער הניתוב בארבע שאלות** (נשאל תמיד):

1. החלטה חדשה? → `DECISIONS.md`
2. לקח חוזר? → `LEARNINGS.md`
3. התקדמות רגילה? → `CHANGELOG.md`
4. מה הסטטוס הבא? → `STANDUP.md`

ועדכון ה-issue ב-Linear בתגובה קצרה. הסשן נסגר במצב שאפשר להמשיך ממנו.

---

## מקרי קצה

| מצב | מה עושים |
|---|---|
| משימה טריוויאלית (Level 0) | בצע ישירות, בלי issue, בלי טקס. |
| אין פרויקט Linear ב-repo | לעבודה אמיתית — עצור והצע להקים פרויקט (ראה `linear/project-routing.md`). |
| feature גדול בלי תוכנית | עצור, תוכנית, אישור, ואז issues. |
| סשן אחר תפס את ה-issue | קח את הבא בתור. Linear הוא הבורר. |
| נגמר הזמן באמצע | `/wrap-up` בכל זאת — עדכן `STANDUP.md` כדי שתמשיך מחר. |

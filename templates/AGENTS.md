# AGENTS.md — תיאום בין סוכנים

> תבנית AgentOS. מגדירה אילו סוכנים/תפקידים פועלים בפרויקט ואיך הם לא מתנגשים.

## עקרון

כמה סוכנים (Claude Code, Codex, וגם עבודה ידנית) עשויים לפעול במקביל.
**Linear הוא הבורר.** כל סוכן עובד על issue אחר ו-branch אחר.

## תפקידים אפשריים

ה-AgentOS לא מחייב את כולם — בחר את מה שרלוונטי לפרויקט:

| תפקיד | אחריות | מתי |
|---|---|---|
| **Builder** | מימוש issues מול Acceptance Criteria | ברירת מחדל — רוב העבודה |
| **Planner / Architect** | פירוק feature לתוכנית ול-issues | לפני עבודת Level 3 |
| **Reviewer** | בדיקת PR מול החלטות וסטנדרטים | לפני מיזוג |
| **Explorer** | חיפוש רחב ב-codebase, איתור קוד רלוונטי | בתחילת משימה לא־מוכרת |
| **Wrap-up agent** | עדכון קבצי memory בסוף סשן | סוף כל סשן |

## כללי אי־התנגשות

1. **בדוק `STANDUP.md` ו-Linear לפני שתתבע issue.** אם issue ו-branch מסומנים כפעילים על ידי סשן אחר — הוא תפוס. בחר את הבא בתור.
2. **נעילה תלת־שכבתית** לכל issue: assignee + status + branch. שלושתם יחד = הוכחת בעלות.
3. **אל תיגע בקובץ שסוכן אחר שינה ב-24 השעות האחרונות** בלי לבדוק ב-Linear קודם.
4. אם branch פתוח על קובץ שאתה צריך — בחר issue אחר או הסלם.

## זרימת מסירה בין סוכנים

- סוכן שמסיים סשן מריץ `/wrap-up` → `STANDUP.md` משקף את המצב המדויק.
- הסוכן הבא מריץ `/prime` → קורא את אותו `STANDUP.md` וממשיך מאיפה שהקודם עצר.

> כך "זיכרון" עובר בין סוכנים שונים בלי שיחה ישירה ביניהם — הקבצים הם הממשק.

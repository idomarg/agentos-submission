# /review-pr — בדיקת PR מול החלטות וסטנדרטים

> Slash command של AgentOS. שער איכות לפני מיזוג.
> מיקום מותקן: `.claude/commands/review-pr.md`

## מטרה

לוודא שה-PR באמת עושה מה שצריך, לא שובר החלטה נעולה, ועומד בסטנדרטים — לפני מיזוג.

## מה הפקודה עושה

1. קוראת את ה-diff של ה-PR.
2. בודקת אותו מול שלושה ממדים:
   - **Acceptance Criteria** של ה-issue — האם כל אחד מהם מסומן בפועל בקוד?
   - **`DECISIONS.md`** — האם משהו ב-PR שובר החלטה נעולה?
   - **סטנדרטי קוד** — האם הקוד נקרא כמו הקוד שסביבו (שמות, idioms, צפיפות הערות)?
3. מריצה/מוודאת את האימות המקומי הרלוונטי (`typecheck`, `build`, `tests`).
4. מסכמת: אישור, או רשימת הערות קונקרטיות לתיקון.

## כללים

- **תקנות correctness לפני העדפות סגנון.** באג שובר > ניסוח יפה.
- אם נשברה החלטה נעולה — זה חוסם, גם אם הקוד "עובד".
- אם בדיקת ה-build/CI נכשלת — להתייחס כאל כשל אמיתי, לא לעקוף.

## פלט

> **PR #<n>** — <אושר / דרושים תיקונים> · **Acceptance**: <X/Y> · **הערות**: <רשימה>.

## מתי משתמשים

לפני מיזוג כל PR לא־טריוויאלי.
